# Private PDF receipt staging

Implement admin/HR-only draft/archive batches (period YYYY-MM, explicit liquidation type) and manually assigned private PDF documents. Staging is not publication, employee receipt, signature, or sending. Supervisors have no receipt API or private audit visibility.

Limits: 5 MiB/PDF, 20 files and 50 MiB/batch, 256 MiB total stored PDFs including archived documents. Validate with pdf-lib in a separate worker: two concurrent validators, 5-second timeout, 128 MiB old-generation / 16 MiB young-generation heap and 40 pages. Worker heap limits are not an OS-wide RSS sandbox; original bytes are not sanitized. Reject malformed/encrypted PDFs; serve only authenticated attachments with no-store/nosniff headers. No ZIP extraction or automatic assignment/splitting.

Storage: immutable SQLite BLOB plus SHA256, sanitized filename, byte count and page count. Batch/hash uniqueness and quota/archive state are rechecked transactionally after validation. Metadata selects explicit columns and audits never contain bytes. Assignment/reassignment require an existing employee and reason; archives preserve bytes and prevent later changes.

Privacy boundary: an isolated synthetic Vite root proved unauthenticated HEAD /@fs/private/synthetic.sqlite returned 200. Never tested a real database. Add development frontend route allowlist, actual configured DB exclusion and frontend-extension restrictions; regression uses only synthetic HEAD paths.
