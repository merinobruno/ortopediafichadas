# Manual weekly planning

Implement versioned employee/day overrides: inherit tombstones, rest, or server-snapshotted shift with optional authorized planned site. Immutable revision history records actor/common reason/time; current revision monotonically increases even after returning to inherit. Planned sites express expectations only and never change attendance permissions, locations or measured records.

1. Add current/history side tables and strict batch/week/history APIs. Scope employees before pagination/totals; admin/HR atomic changed-cell save (50 employees/350 cells maximum), supervisor read only. Validate Monday week, civil dates, duplicate cells, revisions, active catalogs and current site authorization inside one transaction. Enqueue day reconciliation in the same transaction.
2. Resolve override before cyclic-plan fallback in calendar, preserving existing holiday/approved-leave/first-arrival/tolerance/future/overnight handling and exposing expectation origin/planned site. Keep domain attendance untouched.
3. Add responsive team-week UI with staging/common reason, explicit discard, disabled navigation while loading/saving or dirty, stale-request guards and clear conflict handling. Preserve rotations.
4. Tests cover precedence/tombstones/snapshots, atomic rollback and validation, scoped history/pagination, attendance independence, exception reconciliation and DOM asynchronous behavior. Normalize scoped files, full tests/build, then freeze for review/QA.
Completed and scoped-normalized. npm test passed 103/103; npm run build passed TypeScript, client and server/ops packaging. Nine new tests cover override precedence/tombstones, immutable snapshots, authorized actual attendance independence and measured-record byte equality, existing calendar suppressions and exception reconciliation, transactional failure/caps, HTTP scope/history/revision status, and asynchronous UI navigation/explicit discard. No domain attendance mutation code was changed. Parent read-only review/browser QA remain separate checks.
